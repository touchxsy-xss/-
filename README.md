# 声边三端联调演示

## 服务

- `healthpal-nginx`：HTTPS 静态页面和 `/api/` 反向代理
- `healthpal-api.service`：系统 Python 标准库 API
- `data/shengbian.db`：SQLite 持久化数据库

API 仅监听 Docker 的私有网桥 `172.18.0.1:8000`，不直接暴露到局域网；Nginx 是唯一的公开入口。

## 演示身份

页面会自动使用一个演示身份，通过 `X-Demo-User` 请求头传给 API：

- `platform-admin`：平台总运营
- `property-pengyi`：彭一小区物业
- `resident-li`：彭一小区居民李女士

这只是可验证业务权限的小范围演示身份，不是生产级登录。生产接入时应替换为真实的认证会话，并保持 API 的服务端角色和小区校验。

## 已打通的链路

1. 居民提交报修，物业端能加载、受理、转第三方和完成。
2. 居民端会显示同一工单的事件时间线，并可在待确认时确认或重新打开。
3. 物业提交周记，平台审核发布，居民端读取已发布内容。
4. 居民投诉建议、报修图片/视频附件、物业催办事件都会写入数据库并保留审计记录。
5. 物业公告可以创建并提交审核，平台审核发布后与物业周记合并进入居民端首页轮播。

支付入口目前明确保持关闭：项目还没有支付服务商、账单来源、签名校验和退款协议，页面不会显示模拟缴费成功，也不会生成可误用的支付订单。

## 回滚

原静态站点归档在 `/srv/homeserver/rollback/healthpal-static-20260817-224934.tar.gz`。
运行 `/srv/homeserver/rollback/rollback-healthpal-to-static.sh` 会停止 API、恢复归档并启动原始 Nginx 服务。恢复会移除演示 SQLite 数据库，因为它位于被替换的应用目录内。
